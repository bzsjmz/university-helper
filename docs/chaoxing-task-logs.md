# 学习通任务日志

任务详情的“任务日志”显示本轮处理范围、章节失败的环节和重试结果，以及独立的课程作业/考试检查结果。不同任务出现“失败”不意味着原因相同。

例如（示例文案，不是真实账号记录）：

```text
本轮处理范围：章节学习、课程考试
课程【高等数学A】章节【2.1 极限】：第 1/3 次尝试：章节任务列表请求失败（HTTP 403）；稍后重试，先处理其他章节
课程【高等数学A】章节【2.1 极限】：第 2/3 次尝试成功
开始读取课程考试列表
课程考试列表读取失败：无法识别列表，未将其当作空列表；未能确认是否存在待处理项目，不代表考试或作业不及格
课程【高等数学A】处理结束：章节失败 0 项；课程作业/考试未完成或检查异常 1 项。已完成部分保留，具体原因见前面的分项日志。
```

- 章节失败数按章节统计，同一章节的多次尝试不会重复增加最终失败数。任务点会标明视频/音频、文档、章节测验、阅读或直播等环节。
- HTTP 状态、超时、网络连接、数据解析、未开放和线程资源不足等已知原因会单独说明。底层只返回失败状态而没有具体原因时，显示“平台未确认完成”，不能据此认定题库未命中或 AI 出错。
- 作业/考试异常数包含列表检查失败和具体项目处理未完成，不能解释成“不及格的试卷数”。具体作业或考试来源见分项日志。
- 按配置跳过未开放章节会明确提示“跳过不代表平台已完成”。重试成功会补充成功日志。
- 章节百分比不包含课程级作业/考试；少量章节失败或已启用的作业/考试检查异常，都可能使最终任务为失败。该状态不会撤销平台已经确认的完成进度。

诊断信息通过当前任务的回调写入，不抓取全局日志，不把其他账号的错误混进来。新诊断只使用固定分类和 HTTP 状态，不复制异常原文、响应正文、Cookie 或完整请求地址。每个任务沿用最多 1000 条日志的限制；只记录失败尝试和重试恢复结果，不为正常视频的每次上报新增日志。

此功能需要运行包含改动的新后端；旧任务已经缺失的细节无法补回。桌面版需要重新打包安装，服务器需要单独更新后端。日志改进不改变题库链、章节并发、重试次数或平台完成条件，也不等同于修复了日志所指出的业务失败。
